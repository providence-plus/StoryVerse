## 最重要的一条：玩家原话是事实锚句

- 上面 JSON 里每个**非空**字符串都是玩家亲手写下的设定，属于**不可违背的事实**。
- 补写时必须**逐字保留这些原话**，以它为开头或核心句就地扩写。不许改写、不许替换、不许删掉、不许写出与之矛盾的内容。
  例如玩家写「现代校园」，你不能写成「近未来太空站」；玩家写「基调偏甜」，你不能写成「压抑残酷」。
- 玩家**没有写到**的地方才由你补全：没写常穿服饰、没写城市布局、没写势力关系、没写日常规矩，都可以自由补，越具体越好。
- 每一项都要补充，**即使玩家已经写了两句，也要在同一条目里把细节写足写透**。这不是让你压缩内容，恰恰相反：设定越详实，之后展开的故事越细致。

## 各条目要写多细

- `name`：不超过 12 个字。玩家填了就用玩家的，只在空缺时补。
- `genre` / `description`：玩家填了以玩家为准，可顺句式补足信息，不要改事实。
- `setting`：世界观背景，**1200 到 2000 字** Markdown。分小节写：时代与地理、主要场所、势力与人物关系网、日常生活质感、核心矛盾与悬念。要写出名字、数字、物件、习惯、规矩，不要「这是一个充满可能性的世界」这类空话。
- `rules`：世界规则，**600 到 1000 字** Markdown。写清不可违背的硬规则、资源或能力的代价、社会禁忌、叙事上必须保持一致的设定。
- `opening_location`：开场地点名。玩家填了就用玩家的。
- `opening_scene`：开场画面，**250 到 400 字**中文小说笔法，第二人称「你」。只呈现环境、在场人物和一个悬念，**绝对不许替玩家做动作、说台词、决定想法**。
- `opening_choices`：恰好四项 A/B/C/D，每项是一个玩家能直接点选的具体行动。玩家填过的选项原样保留，缺的补全。
- `protagonist_hint` / `npc_hints`：只给一句话方向建议，不要生成人物卡。

所有人物都必须是明确成年的虚构角色。不要把其他作品的世界名、人物名直接搬进来。

## 严格输出以下 JSON，不要包代码块以外的解释文字

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。Markdown 分段也用 `\n\n` 表示。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，引用、强调、台词一律用中文引号「」或『』。
- 字符串里若出现反斜杠，只用于 `\n` 这类转义；不要写 Windows 路径或多余的 `\`。
- 所有字段都必须出现，最后以 `}` 完整收尾。**不要中途收尾、不要省略字段、不要写「（此处省略）」**。
- JSON 之后不要追加任何总结、注释或解释文字。
- 达到上面的字数目标后立刻输出**完整闭合的 JSON** 收尾，不要继续铺陈、不要重复已经写过的段落。

```json
{
  "name": "世界名",
  "genre": "类型 / 基调",
  "description": "两三句话，说清这是个什么世界、故事从哪开始",
  "setting": "完整的世界观背景 Markdown",
  "rules": "世界规则 Markdown",
  "opening_location": "开场地点名",

```

任何一个字段都不许是 null；`opening_choices` 必须恰好四项，`npc_hints` 必须是字符串数组。
