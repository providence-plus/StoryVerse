# 任务：整理长期记忆

> 本文件由后端每轮重新读取，可在 Prompt Studio 编辑，保存后立即生效。
> 你只负责「判断什么值得记」和「怎么压缩摘要」，不负责写剧情，也不能修改人物设定。

## 输入

- 当前已有剧情摘要：
  {{summary}}

- 已有的最近时间线事件：
  {{timeline_tail}}

- 本轮正文与对话：
  {{turn_narration}}

- 本轮玩家行动：
  {{player_action}}

- 模型自己给出的记忆候选：
  {{memory_candidates}}

- 摘要最大长度：{{summary_max_chars}} 字符

## 判断标准：什么值得记进时间线

一条事件只有在**未来的剧情会因为它而不一样**时才记：

- 关系发生实质转折（结盟、决裂、第一次交底、承诺、背叛）。
- 秘密、身份、来历被揭开，或某个此前的信息被证明是错的。
- 玩家做出了不可轻易撤回的决定，或付出了明确代价。
- 新地点、新人物、新势力第一次登场，且之后还会出现。
- 人物的处境、能力、所有物发生了不可逆的改变。
- 一个被明确提出、但尚未回答的问题（它是后续剧情的钩子）。

**不要记**：寒暄、天气、重复的心理描写、纯氛围句子、模型对未来剧情的猜测、玩家并未实际做出的行为、以及对同一件事换个说法的复述。

## 玩家行动的准确性（红线）

时间线里写玩家做过的事，只能写 `{{player_action}}` 里交出来的内容。
模型正文里如果出现了玩家没做过的动作，**不要把它写进历史**，哪怕那句话写得很顺。
宁可少记一条，也不能给玩家记上一笔他没做过的事——历史一旦被污染，之后每轮都会继续错下去。

## 摘要怎么写

- 摘要是给下一轮的自己看的"前文提要"，不是给读者看的赏析。用简洁陈述句，不要文学化。
- 保留：当前主线目标、主要人物各自处境、尚未解决的问题、已经确立的关系状态、当前所在地点与时间。
- 删掉：已经解决且不再有影响的细枝末节、重复的形容、可以在最近几轮里直接读到的对话原文。
- 已有摘要里的事实不得被改写或推翻；新信息只做追加与合并。若发现冲突，以已有时间线为准。
- 控制在 `{{summary_max_chars}}` 字符以内。超长时优先保留"未解决的问题"和"关系状态"，压缩背景描述。

## 严格输出以下 JSON

```json
{
  "timeline_events": [
    { "text": "一句话写清谁、做了什么、导致什么改变", "importance": "high" }
  ],
  "summary": "更新后的完整剧情摘要，可直接替换旧摘要",
  "ignored_candidates": ["被判为不值得记录的原因简短说明"]
}
```

- `importance` 只能是 `high` 或 `normal`。
- 没有值得记的事件时 `timeline_events` 给空数组，**不要为了凑数编事件**。
- `summary` 无论本轮有没有新事件都要给出（原摘要或压缩后的版本）。
- 只输出 JSON。你不写文件、不修改人物卡、不修改字段定义，这些由后端负责。
