# 任务：把一句话扩展成完整的 NPC 人物

> 本文件由后端每次生成前重新读取，可在 Prompt Studio 编辑，保存后立即生效。
> 人物有哪些字段**完全由用户定义**，见 `{{panel_schema_json}}`，本文件不预设任何字段名。

## 输入

- 世界设定与规则：
  {{world_context}}

- 主角人物卡与当前状态：
  {{protagonist_json}}

- 本世界 NPC 字段定义（字段键、名称、说明、类型、更新规则、枚举选项）：
  {{panel_schema_json}}

- 用户给的核心描述：
  {{user_description}}

- 本次需要生成的数量与总体要求：
  {{generation_request}}

## 你要做什么

把用户那一两句核心描述，长成一个能在长期剧情里站得住的成年虚构人物。核心描述是**不可违背的锚点**，你补的是它没写的部分，不是把它改写成另一个人。

### 人物要有层次，不要贴标签

- **动机**要具体到一个想要的东西，并写清它为什么想要、眼下被什么挡着。不要写"追求真理""渴望自由"这种放谁身上都成立的空话。
- **成长经历**要能解释现在的性格：哪一段经历留下了什么习惯、什么回避、什么下意识的反应。经历与性格之间必须有看得见的因果。
- **性格层次**至少写出一组张力：外表呈现的样子，和底下真正驱动他的东西，二者不完全一致但不是简单反转（例如"处处讲规矩，是因为曾经因一次破例失去过很重要的人"）。
- **恐惧与秘密**要能变成剧情：恐惧会在什么情境下被触发，秘密一旦暴露会牵动谁。不要写成装饰性的设定条目。
- **语言风格**要具体到可模仿：句子长短、称呼习惯、是否爱反问、生气时话变多还是变少。

### 与主角的关系

- 给一个明确的**初始关系位置**：因何相识、当前彼此的立场、各自的误判，以及这段关系里最容易被碰到的一根刺。
- 关系不要一上来就亲密或敌对到底，留出可以移动的余地；也不要把 NPC 写成专门为主角服务的功能性角色，他得有自己的日程和打算。

### 避免模板化

- 不要用"傲娇但内心善良""外冷内热""高冷禁欲"这类现成标签直接复述用户的话当作人设，要把它拆成具体的生活痕迹和反应方式。
- 同一批生成多个 NPC 时，彼此在出身、说话节奏、处事方式、在意的东西上必须明显不同，不要只是换了名字和职业的同一个模板。
- 名字要贴合世界背景，避免同一批出现读音或字形相近的名字。

### 剧情钩子

每个人至少埋一个能立刻被用上的钩子：一个尚未解释的细节、一件他正在回避的事、一个和主角目标相撞的小冲突。钩子要能被写进下一轮正文，而不是一句抽象的"身世成谜"。

## 动态字段补齐（最重要的部分）

- `{{panel_schema_json}}` 里列了哪些字段，你就要为**每一个**字段给出合理的初始值。用户只给了一句话，其余都要靠你结合世界设定、主角卡和上面的人物设计补齐。
- 逐字段读懂 `description`（这个字段到底指什么）和 `type`（值该长什么样），不要按字段名望文生义。
- 值必须符合类型：`text` / `long_text` 给字符串，`number` 给数字，`boolean` 给 true 或 false，`enum` 只能从该字段的预设选项里选，`list` 给数组，`key_value` 给对象。
- 所有值要与人物设定自洽：一个养尊处优的人，服饰、举止、对金钱的态度、对陌生环境的反应应当互相印证；不要出现彼此打架的设定。
- 字段里若包含"与主角的关系""对主角的评价"这类内容，值要与上面设计的初始关系一致。
- **不要输出 schema 里没有的字段，也不要新增、改名、删除字段。** 字段定义只能由玩家在 Panel Designer 里改。
- 成年年龄：所有角色必须是明确成年人。若字段涉及年龄，给 20 岁以上的值。

## 严格输出以下 JSON

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。人物定位、背景、内心想法这类长文本尤其注意。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，需要引用、写台词时一律用中文引号「」或『』。
- 字符串里的反斜杠只用于 `\n` 这类转义，不要写多余的 `\`。
- 所有字段都必须出现，最后以 `}` 完整收尾；**不要中途收尾、不要省略字段、不要写「（此处省略）」**。
- JSON 之后不要追加任何总结、注释或解释文字。

**内容长度：写足写透，不要为了省字数牺牲细节。** 后端已给足长度预算。批量生成多人时若接近上限，优先保证每个人物的 `custom_fields` 覆盖全部字段且 JSON 闭合。

```json
{
  "characters": [
    {
      "name": "人物姓名",
      "core_description": "把用户的一句话连同必要补充压缩成两三句人物定位",
      "custom_fields": {
        "字段键": "符合该字段类型的值"
      },
      "plot_hooks": ["可被下一轮正文直接使用的一个剧情钩子"]
    }
  ],
  "relationships_between_generated": [
    { "from": "人物姓名", "to": "人物姓名", "relation": "两人之间的具体关系与张力" }
  ]
}
```

- `characters` 的数量必须等于本次要求生成的数量。
- 批量生成且要求"自动设计人物之间的关系"时，才填 `relationships_between_generated`；否则给空数组。
- `custom_fields` 必须覆盖 `{{panel_schema_json}}` 中的每一个字段键，一个不多、一个不少。
- 只输出 JSON，不要解释、不要寒暄、不要写成 Markdown 列表。

## 注意

这一步只产出**预览**，后端会校验字段与类型、前端会展示给玩家编辑，玩家点确认之后才会写进人物文件。所以不要试图输出任何"已保存"之类的措辞，也不要输出文件操作指令。
