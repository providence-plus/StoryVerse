## 最重要的一条：玩家原话是事实锚句

- 每个非空 `player_input` 都是玩家亲手写下的设定，属于**不可违背的事实**。
- 补写时必须**逐字保留这些原话**，以它为开头或核心句就地扩写。不许改写、不许替换、不许删掉、不许写出与之矛盾的内容。
  例如玩家写「红发，个子很高」，你不能写成「一头黑发、身量娇小」；玩家写「三年前那场事故」，不能改成别的年份或别的事件。
- 玩家**没有写到**的地方才由你补全：外貌里没写常穿服饰、没写惯常神态，性格里没写面对压力时的反应，背景里没写家庭与成长节点，都可以自由补，越具体越好——但补出来的内容必须和已有事实兼容。
- **每一项都要补充，即使玩家已经写了一两句，也要在同一条目里把细节写足写透**。这不是让你压缩内容：人物设定越详实，之后围绕他展开的故事越细致。
- 关系卡里 `target_character_id` 必须原样沿用，不许换人；`relation` 与 `past_events` 里的玩家原话同样逐字保留。

## 各条目要写多细

- `name`：玩家填了就用玩家的；只在空缺时按已有设定起一个中文名。
- `core_description`：一句话人物定位，玩家填了以玩家为准。
- `appearance`：**400 到 600 字**。五官、身形、发色发质、常穿服饰与配饰、习惯性姿态、声音、给人的第一印象。写能拍出来的具体细节，不要堆形容词。
- `personality`：**500 到 700 字**。核心性格与它的来处、说话方式、对压力与冲突的第一反应、在亲密关系里的表现、不愿示人的一面、明确的底线。要让行为能被推得出来。
- `background`：**700 到 1000 字**。家庭与成长环境、教育与职业经历、经济状况、重要地点、塑造当下的那几件事、现在的处境与未解决的牵挂。
- `major_events`：玩家写的每一条都要保留，并各自扩成 **200 到 300 字**的完整事件（时间、地点、在场者、发生了什么、留下了什么后果）。玩家没写时可以补 2 到 3 条与背景自洽的重大事件。一条一段，用 `\n\n` 分段。
- `relation`：**400 到 600 字**。两人如何认识、当前关系的准确定位、彼此的称呼与说话分寸、公开面貌与私下真相、张力在哪里。
- `past_events`：每一条扩成 **150 到 250 字**的具体场景（谁先开口、当时在哪、之后关系怎么变的），事实部分以玩家原话为准。

所有人物都必须是明确成年的虚构角色。不要把其他作品的人物名直接搬进来。

## 严格输出以下 JSON，不要包代码块以外的解释文字

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。分段用 `\n\n`。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，引用、台词一律用中文引号「」或『』。
- 字符串里若出现反斜杠，只用于 `\n` 这类转义。
- 所有字段都必须出现，最后以 `}` 完整收尾。**不要中途收尾、不要省略字段、不要写「（此处省略）」**。
- JSON 之后不要追加任何总结、注释或解释文字。
- 达到上面的字数目标后立刻输出**完整闭合的 JSON** 收尾，不要继续铺陈、不要重复已经写过的段落。

```json
{
  "name": "角色姓名",
  "core_description": "一句话人物定位",
  "items": {
    "appearance": {"text": "完整的外貌设定"},
    "personality": {"text": "完整的性格设定"},
    "background": {"text": "完整的背景设定"},
    "major_events": {"text": "重大事件，一段一件"}
  },
  "relations": [
    {
      "target_character_id": "原样沿用玩家选的角色 ID",
      "target_name": "该角色名字",
      "relation": {"text": "完整的关系设定"},
      "past_events": [{"text": "一条已发生关键事件的完整场景"}]
    }
  ]
}
```

`items` 的四个键必须齐全，`relations` 必须输出与输入**同样数量**的卡片、顺序一致；没有内容时给空数组或空字符串，不许省略键。
**绝对不要输出 `planned_events` 或 `player_input`**：这两类由程序原样保留，不经你改写。
