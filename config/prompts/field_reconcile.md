# 任务：定期校准人物字段值

> 本文件由后端在「事件触发」或「每 N 轮兜底」时读取，可在 Prompt Studio 编辑，保存后立即生效。
> 默认 N=8（与最近上下文窗口对齐），可在 config/generation_config.yaml 里改成任意值或设为 0 关闭。
> 校准不是重新生成人物：绝大多数情况下你应当返回空数组。

## 为什么要校准

每轮剧情里，模型会顺手提交"这一轮变了"的字段。但它偶尔会漏——
例如正文里人物明明换了一身衣服，却忘了提交；或者某个通常固定的字段其实该变了。
你的工作是**回头对一遍**，把这类漏写补上，顺便发现明显和已发生事实打架的旧值。

## 输入

- 世界设定与规则：
  {{world_context}}

- 角色固定人物卡（只读，不许改）：
  {{character_profile_json}}

- 字段定义（每个字段的说明、类型、更新规则）：
  {{panel_schema_json}}

- 角色当前全部字段值：
  {{current_fields_json}}

- 剧情摘要：
  {{summary}}

- 最近若干轮的时间线事件与互动：
  {{recent_history}}

- 当前地点与在场人物：
  {{current_context}}

## 判断准则（宁缺毋滥）

**只在下面两种情况才提交修正：**

1. 最近剧情里发生了明确、无歧义的事件，而当前字段值与之直接矛盾（正文写了换装，值还是旧衣服）。
2. 某个字段值明显与人物固定设定或世界规则冲突，属于早先写错了。

**以下情况一律不要提交：**

- 只是"可以写得更生动""可以补充细节"。校准不是润色。
- 你推测人物内心大概有了变化，但正文没有明写。不许替 NPC 编心里戏，更不许替玩家决定想法。
- `update_policy` 为 `static` 的字段：无论发生什么都不要动。
- `mostly_static` 的字段：除非有白纸黑字的事件，否则不动。
- 任何你没有把握的字段。**返回空数组是完全正确、也是最常见的答案。**

## 约束

- 只输出**需要修正**的字段键，绝不要把全部字段重发一遍。
- 值必须符合该字段的 `type`：`text` / `long_text` 字符串、`number` 数字、`boolean` 布尔值、`enum` 只能选预设项、`list` 数组、`key_value` 对象。
- 只能使用 `{{panel_schema_json}}` 里存在的字段键。不许新增、删除、改名任何字段，不许改字段定义。
- 不许改动 `profile.yaml` 里的固定设定，不许改写历史，不许补写玩家没做过的行为。
- 每条修正都要给出依据，指明是哪一轮、哪件事导致的。

## 严格输出以下 JSON

```json
{
  "corrections": [
    {
      "field_id": "需要修正的字段键",
      "value": "符合该字段类型的新值",
      "reason": "依据哪一段已发生的剧情"
    }
  ]
}
```

- 没有需要修正的字段时输出 `{"corrections": []}`。**不要为了显得有用而制造修正。**
- 只输出 JSON。后端会用和正常回合完全相同的校验器检查键、类型与更新规则，非法项会被丢弃。
