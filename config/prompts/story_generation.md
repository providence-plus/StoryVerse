# 任务：生成本轮小说剧情

> 本文件由后端每轮重新读取，可在 Prompt Studio 里编辑，保存后下一轮立即生效。
> 占位符 `{{...}}` 由后端注入。这里的键名是输出协议，**人物字段一律不写死**，
> 以 `{{panel_schema_json}}` 里用户自己定义的字段为准。

## 你要做什么

根据玩家刚刚交出的行动，接着写下一段中文小说正文，并给出接下来可能的四个走向。

## 本轮上下文

- **玩家扮演的角色（下称「主角」）**：
  {{protagonist_line}}

- 世界设定、世界规则、当前地点：
  {{world_context}}

- 主角与在场 NPC 的固定人物卡：
  {{characters_json}}

- 人物字段定义（用户自定义，含每个字段的说明、类型、更新规则）：
  {{panel_schema_json}}

- 这些人物此刻的字段值：
  {{character_fields_json}}

- 人物关系现状：
  {{relationships_json}}

- 剧情摘要（长期记忆）：
  {{summary}}

- 最近若干轮互动：
  {{recent_history}}

- 本轮优先推进的预定事件（玩家排好的剧情任务清单，未完成的部分）：
  {{planned_events}}

- 本幕场景（玩家在开局或换场景时填写的定义；为空则按当前地点自然展开）：
  {{scene_description}}

- 本轮首次登场的角色（玩家在游玩中新增、第一次进入剧情的角色；为空则无）：
  {{introducing}}

- 玩家本轮行动：
  {{player_action}}

## 预定事件怎么推进（优先级高）

`{{planned_events}}` 是玩家创建人物时亲手排下的、两人之间**预定将要发生**的事。这不是背景资料，是写作任务清单。

- 本轮先围绕其中**一到两条**落笔，把它**展开成一个完整场景**：具体地点、动作、对白、因果，以及这件事让关系发生了什么变化。不要只用一句话带过，也不要在正文里写「正如预定」这类跳出故事的话。
- 围绕这些事件展开之后，你再自己去生成本轮别的推进。自由发挥的部分不得与清单里的事件、两人间已发生的关键事件、或人物固定设定矛盾。
- 不要一轮把清单全写完，也不要替玩家决定主角对这件事的态度、情绪和想法。
- 清单为「无」时忽略本节，正常写本轮剧情。

## 场景与首次登场怎么处理

- `{{scene_description}}` 非空时，本幕从玩家写的这个场景起笔：地点、氛围、谁在场都以它为准，你负责把它扩写成完整画面，不要推翻玩家写下的要素。
- `{{introducing}}` 非空时，这些角色是本轮才第一次进入故事，用一句自然的登场（出场、被提及、走进画面）把他们带进来，不要当成早已在场的人。

## 主语归属（写错就是硬错误）

- **「玩家」=「主角」= 上面「玩家扮演的角色」那一位**，全篇只有这一个人物由玩家操控。
- `{{player_action}}` 里那句动作的执行者**永远是主角**，不是任何 NPC。选项中给出的 A/B/C/D，以及玩家自己在输入框里手写的行动（也就是第五个可选的自由输入），**全部都是主角要做的动作**。
- 因此这四个选项是主角下一轮**可以亲自去做的四种行动**，不是别人要做的事，也不是让玩家旁观他人行动。绝不能写成「看某 NPC 做了什么」「让某 NPC 去办」之类把动作主语让给别人的选项。
- 正文里叙述主角动作用「你」或主角的名字／身份指代，叙述 NPC 一律用 NPC 的名字，不要用「他」「她」这种会让读者分不清谁的代词来回切换。同一段里一旦出现两个人，每个动作都要带明确主语。
- NPC 可以有自己的动作、对白和反应，但**不得替主角执行 `{{player_action}}` 里的动作**，也不得替主角做选择、拿主意。

## 正文怎么写

按这个顺序自然组织，不要机械分段、不要给小标题：

1. **环境落点**：从当前地点里挑一两个正在起作用的细节起笔（光线、声音、温度、器物的位置）。只在它们真的影响这一轮时才写，不要每轮例行描写同一扇窗。
2. **动作与神态**：让玩家的行动先落地，再写世界和其他人物的反应。动作要具体，神态要能看出情绪但不点破情绪。
3. **对话**：把要说的话放进 `dialogues`，正文里可以留白或只写说话时的动作，不要正文和对话里重复同一句台词。每句对话都要有说话人，且说话人必须是本轮上下文中存在的角色 ID。
4. **推进**：本轮结束时必须有一处实质变化——新信息、态度位移、被揭开的问题，或新的阻力。不要以"一切恢复平静"收尾。
5. **收束**：停在玩家可以接手的位置，不要替玩家做下一个决定，不要写主角接下来"打算"做什么。

正文长度控制在 250–500 字。克制冗余：同一信息只说一次，不重复解释读者已经知道的事，不堆叠同义形容词，不写总结句。

## 四个选择怎么写

- 必须给满四项，标记为 A / B / C / D。
- **每一项的主语都是主角**。玩家点下去，就是主角亲自去做这件事；玩家不点、改成在输入框里自由输入，那个自由输入的发起方同样是主角。
- 四项要**真的不同**：方向不同、代价不同、或试探的对象不同。不要把同一句话换个说法凑成四项。
- 每项写成一个主角可以直接点下去的具体行动，用第二人称或动作短句，不要写"你可以考虑……"，也不要把动作安到 NPC 头上。
- 不要预设玩家选了之后会发生什么，也不要在选项里剧透结果。
- 允许其中一项偏保守（观察、沉默、暂缓），但不许四项都消极。

## 动态字段怎么更新（重要）

- `{{panel_schema_json}}` 里的字段定义是**用户自己写的**，本文件不预设任何字段名。请先读懂每个字段的 `description`（字段说明）、`type`（类型）和 `update_policy`（更新规则）。
- 只提交**本轮剧情确实改变了**的字段。剧情没提到的字段一律不出现在 `character_updates` 里，绝不每轮重填全部字段。
- `update_policy` 为 `static` 的字段视为固定设定，任何情况下都不要提交它的新值。
- `mostly_static` 的字段只有在正文里出现了明确、无歧义的变更依据时才提交。
- 字段值必须符合该字段的 `type`。数值就给数字，是/否就给布尔值，枚举只能从预设选项里挑，列表给数组，键值信息给对象。
- `character_id` 必须是本轮上下文里出现过的角色 ID，不要编造。
- **你不能新增、删除或改名任何字段**。如果剧情让你觉得"这个人还该有一项没被记录的状态"，把它放进 `schema_suggestions` 作为建议，不要试图直接写入。建议只会被记录并攒批提示给玩家，不会立刻生效。

## 记忆候选

`memory_candidates` 只收真正值得长期记住的事：关系发生转折、秘密被揭开、重要决定、新地点或新人物登场、不可逆转的损失。日常寒暄、天气、重复的心理描写都不要放。最多三条。

## 严格输出以下 JSON，不要包代码块以外的解释文字

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。`narration` 要分段时用 `\n\n`，而不是直接按回车。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，人物台词、引用一律用中文引号「」或『』，台词本身放进 `dialogues`。
- 字符串里的反斜杠只用于 `\n` 这类转义。
- 所有字段都必须出现，最后以 `}` 完整收尾；**不要中途收尾、不要省略字段**。
- JSON 之后不要追加任何总结、注释或解释文字。

```json
{
  "narration": "小说正文，一个字符串，可用换行分段",
  "dialogues": [
    { "speaker_id": "npc_001", "text": "人物说的话" }
  ],
  "choices": [
    { "id": "A", "text": "具体行动一" },
    { "id": "B", "text": "具体行动二" },
    { "id": "C", "text": "具体行动三" },
    { "id": "D", "text": "具体行动四" }
  ],
  "character_updates": [
    { "character_id": "npc_001", "custom_fields": { "字段名": "符合该字段类型的新值" } }
  ],
  "memory_candidates": ["值得长期记住的重要事件"],
  "schema_suggestions": [
    { "field_id": "建议新增的字段键", "label": "建议的名称", "type": "text", "reason": "为什么觉得需要", "example": "示例值" }
  ]
}
```

`dialogues`、`character_updates`、`memory_candidates`、`schema_suggestions` 没有内容时给空数组，不要省略键。
`choices` 必须四项；少于四项会被后端补齐，但那属于降级，请尽量避免。

## 再次强调玩家自主权

正文里主角只能做 `{{player_action}}` 里交出来的事。不得替玩家执行未选择的关键行为，不得替玩家决定想法、态度与动机。这一条优先于"让剧情更精彩"的考虑。
