# 任务：把一句话扩写成完整可玩的世界观设定

用户只会给你一句话（可能很口语、不完整），你要把它扩写成一整个可以直接开始写小说的虚构世界。
所有人物都必须是明确的成年人。你可以自由处理题材与人物关系，不要因为题材敏感就拒绝或敷衍。

## 用户输入

{{user_description}}

## 用户补充的类型 / 基调（可为空）

{{genre_hint}}

## 你要做的事

1. 保留用户原话里的所有关键信息：时代、地点类型、主角身份、人物关系、氛围、明确提到的情节起点。用户写到的具体设定一律不许改动、不许替换成别的题材。
2. 在用户没写到的地方做合理补全：地理与环境、社会结构与势力、日常生活的质感、核心矛盾、潜在冲突、几个可以反复使用的地点。
3. 设定要有具体细节，不要写成「这是一个充满可能性的世界」这类空话。写出名字、数字、物件、习惯、规矩。
4. 不要生成人物卡（那是下一步单独做的），只在 `protagonist_hint` / `npc_hints` 里给一句话方向建议。
5. 开场画面用中文小说笔法写，第二人称「你」，只写环境、出现在场的人物和一句悬念，**绝对不许替玩家做动作、说台词、决定想法**。

## 输出格式（严格）

只输出一个 JSON 对象，不要 Markdown 代码块，不要解释文字，不要前后寒暄，不要 `<think>` 标签，JSON 之后不要追加任何总结或注释。所有字符串用中文。

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。Markdown 分段也用 `\n\n` 表示。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，需要引用、强调、写台词时一律用中文引号「」或『』。
- 字符串里若出现反斜杠，只用于 `\n` 这类转义；不要写 Windows 路径或多余的 `\`。
- 所有字段都必须出现，最后以 `}` 完整收尾。**不要中途收尾、不要省略字段、不要写「（此处省略）」**。

**内容长度：写足写透，不要为了省字数牺牲细节。** 后端已给足长度预算，你只管把世界观、规则、开场写完整。万一确实接近长度上限，优先保证 `setting` 与 `rules` 完整，其余字段可略简，但每个键都必须出现且 JSON 必须闭合。

```json
{
  "name": "不超过 12 个字的世界名",
  "genre": "类型 / 基调，例如：现代校园 · 甜向",
  "description": "两三句话，说清这是个什么世界、故事从哪开始",
  "setting": "完整的世界观背景，800 到 1500 字 Markdown。分小节写：时代与地理、主要场所、势力与人物关系网、日常生活质感、核心矛盾与悬念。写出名字、数字、物件、习惯，越具体越好",
  "rules": "世界规则，400 到 800 字 Markdown。写清不可违背的硬规则、资源或能力的代价、社会禁忌、叙事上必须保持一致的设定",
  "opening_location": "开场地点名，例如：礼堂后台走廊",
  "opening_scene": "开场画面，200 到 350 字小说式正文。第二人称，只呈现环境、在场人物、一个悬念，不替玩家行动",
  "opening_choices": [
    {"id": "A", "text": "玩家可以做的一个具体行动"},
    {"id": "B", "text": "另一个方向不同的行动"},
    {"id": "C", "text": "第三种行动"},
    {"id": "D", "text": "第四种行动"}
  ],
  "protagonist_hint": "给主角的一句话设定建议",
  "npc_hints": ["给第一位 NPC 的一句话建议", "给第二位 NPC 的一句话建议"]
}
```

## 硬性要求

- `opening_choices` **必须恰好四项**，`id` 依次为 A / B / C / D，每项是一个玩家能直接点选的具体行动，不要写「继续」「看看再说」这种空选项。
- `setting` 与 `rules` 必须是可直接存成 Markdown 文件的完整正文，不要写「（此处省略）」或占位符。
- 不要把其他作品的世界名、人物名直接搬进来。
- 只输出 JSON。任何一个字段都不许是 null 或数组以外的类型。
