# 任务：把一句话扩展成完整的主角卡

> 本文件由后端每次生成前重新读取，可在 Prompt Studio 编辑，保存后立即生效。
> 主角有哪些字段完全由用户定义，见 `{{panel_schema_json}}`，本文件不预设任何字段名。

## 输入

- 世界设定与规则：
  {{world_context}}

- 本世界主角字段定义（字段键、名称、说明、类型、更新规则、枚举选项）：
  {{panel_schema_json}}

- 用户给的核心描述：
  {{user_description}}

## 主角和 NPC 不一样

主角是玩家要长期扮演的人，因此你的补写要**留出空地**，不能替玩家把人设定死：

- 可以补足出身、经历、外貌、处境、能力、社会关系、眼下要解决的事。
- **不要写死主角的性格定论、内心信念、价值观、对他人的最终态度，也不要写"他其实是个……的人"这类替玩家下结论的句子。** 这些留给玩家在每一轮里用行动回答。
- 不要替主角预设详尽的过往心理创伤并据此规定他以后会怎么反应；经历可以写，但解释权归玩家。
- 动机写成"眼下被什么处境推着走"，而不是"他这一生注定要追求什么"。玩家完全可能中途改方向。

## 一句话怎么长成人物

- 用户给的每一句都是锚点，不得改写、不得稀释。补的是它没说的部分。
- 把抽象描述落成可写进小说的东西：与其说"身手不凡"，不如交代他曾在什么环境里养成了什么习惯，以及这个习惯今天会怎样显露。
- 出身与现今处境之间要有因果，能力与代价要配得上，别给一个没有来由的全能设定。
- 给一个**开场即存在的处境**：一件悬而未决的事、一个刚到达的地点、或一段还没处理的关系，让玩家第一回合就有可以接手的东西。
- 主角必须与世界设定自洽：世界里没有的能力不要给，世界里正在发生的事最好能轻轻擦到他。

## 动态字段补齐

- `{{panel_schema_json}}` 里列了哪些字段，就要为**每一个**字段给出合理初始值。
- 逐字段读懂 `description` 与 `type`，不要望文生义。值必须符合类型：`text` / `long_text` 字符串、`number` 数字、`boolean` 布尔值、`enum` 只能选预设项、`list` 数组、`key_value` 对象。
- 若字段涉及"当前状态"（例如当下穿着、所在位置、身体或处境状态），给一个和开场处境一致的起点，方便第一回合直接续写。
- 若字段涉及"与他人的关系"或"内心想法"，只写**外部可观察的起点或尚未定论的悬念**，不要替玩家做内心判断。
- **不要输出 schema 里没有的字段，也不要新增、改名、删除字段。**
- 主角必须是明确成年人；涉及年龄的字段给 20 岁以上的值。

## 严格输出以下 JSON

**JSON 格式红线（违反就无法被程序读取）：**
- 字符串里的换行一律写成两个字符 `\n`，**禁止在字符串中间按真实回车换行**。人物定位、经历、处境这类长文本尤其注意。
- 字符串值内部**禁止出现 ASCII 双引号 `"`**，需要引用时一律用中文引号「」或『』。
- 字符串里的反斜杠只用于 `\n` 这类转义，不要写多余的 `\`。
- 所有字段都必须出现，最后以 `}` 完整收尾；**不要中途收尾、不要省略字段**。
- JSON 之后不要追加任何总结、注释或解释文字。

**内容长度：写足写透，不要为了省字数牺牲细节。** 后端已给足长度预算，`custom_fields` 必须覆盖全部字段且 JSON 闭合。

```json
{
  "name": "主角姓名",
  "core_description": "两三句人物定位，保留用户原话的核心设定",
  "custom_fields": {
    "字段键": "符合该字段类型的值"
  },
  "opening_situation": "一段可直接作为第一回合开场的处境描述，80 字以内"
}
```

- `custom_fields` 必须覆盖 `{{panel_schema_json}}` 中的每一个字段键，一个不多、一个不少。
- 只输出 JSON，不要解释、不要寒暄。

## 注意

这一步只产出**预览**。后端校验字段与类型后，前端展示给玩家编辑，玩家点确认才会写进人物文件。不要输出"已保存"或任何文件操作指令。
